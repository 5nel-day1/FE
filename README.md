# 🏫 Campus Catch

> 불편이 문제가 되기 전에, 캠퍼스의 이상 신호를 먼저 발견한다.

## 📖 서비스 소개

Campus Catch는 **학생들의 캠퍼스 불편 제보를 AI가 분석하여 반복되거나 증가하는 문제의 이상징후를 발견하고, 관리자가 문제가 커지기 전에 대응할 수 있도록 돕는 AI 기반 캠퍼스 문제 탐지 서비스**입니다.

학생들이 학교생활 중 겪는 시설 · 위생 관련 불편은 각각 작은 문제처럼 보이지만, 같은 장소에서 비슷한 문제가 반복된다면 하나의 문제를 나타내는 신호일 수 있습니다.

Campus Catch는 학생이 작성한 제보를 AI가 분석하여 **장소, 시설, 문제 유형 등의 정보를 파악하고 유사한 제보를 연결**합니다.
반복되거나 증가하는 문제를 이상징후로 판단하여 관리자에게 전달하고, 관리자는 문제를 확인하고 처리할 수 있습니다.

학생은 자신이 작성한 제보의 처리 상태와 결과를 확인할 수 있습니다.

## ✨ 주요 기능

| 기능 | 설명 |
| --- | --- |
| 📝 **캠퍼스 불편 제보** | 학생이 장소와 문제 상황을 작성하여 캠퍼스 내 불편 사항을 제보합니다. |
| 🤖 **AI 제보 분석** | 작성된 제보를 AI가 분석하여 장소, 시설, 문제 유형 등을 파악합니다. |
| 🔗 **유사 제보 연결** | 비슷한 장소와 문제에 대한 제보를 하나의 문제로 연결합니다. |
| 🚨 **이상징후 탐지** | 반복되거나 증가하는 제보를 분석하여 점검이 필요한 문제를 발견합니다. |
| 📊 **관리자 문제 확인** | 관리자가 발견된 문제와 관련 제보를 확인하고 처리합니다. |
| ✅ **처리 결과 확인** | 학생이 자신이 작성한 제보의 처리 상태와 결과를 확인합니다. |

## 🔄 User Flow

```
학생 불편 제보
      ↓
AI 제보 분석
      ↓
유사 제보 연결
      ↓
이상징후 탐지
      ↓
관리자 문제 확인
      ↓
문제 처리
      ↓
학생 처리 결과 확인
```

## 🎯 Git Convention

- 🎉 **Start** : Start New Project `[:tada:]`
- ✨ **Feat** : 새로운 기능 추가 `[:sparkles:]`
- 🐛 **Fix** : 버그 수정 `[:bug:]`
- 🎨 **Design** : CSS 등 사용자 UI 디자인 변경 `[:art:]`
- ♻️ **Refactor** : 코드 리팩토링 `[:recycle:]`
- 🔧 **Settings** : 설정 파일 수정 `[:wrench:]`
- 🗃️ **Comment** : 필요한 주석 추가 및 변경 `[:card_file_box:]`
- ➕ **Dependency/Plugin** : 라이브러리 추가 `[:heavy_plus_sign:]`
- 📝 **Docs** : 문서 수정 `[:memo:]`
- 🔀 **Merge** : 브랜치 병합 `[:twisted_rightwards_arrows:]`
- 🚀 **Deploy** : 배포 관련 작업 `[:rocket:]`
- 🚚 **Rename** : 파일 및 폴더 이름 수정 `[:truck:]`
- 🔥 **Remove** : 파일 삭제 `[:fire:]`
- ⏪️ **Revert** : 이전 버전으로 롤백 `[:rewind:]`

## 🌲 Branch Convention

- `main` : 배포 가능한 브랜치
- `develop` : 개발 브랜치
- `feat/#이슈번호/명칭` : 새로운 기능 개발 브랜치
  - 예시 : `feat/#12/home`
- `fix/#이슈번호/명칭` : 버그 수정 브랜치
  - 예시 : `fix/#12/home`
- `ui/#이슈번호/명칭` : UI 작업 브랜치
  - 예시 : `ui/#12/home`
- `docs/#이슈번호/명칭` : 문서 작성 및 수정 브랜치
  - 예시 : `docs/#12/readme`
- `api/#이슈번호/명칭` : API 연동 작업 브랜치
  - 예시 : `api/#12/home`
- `refactor/#이슈번호/명칭` : 리팩토링 작업 브랜치
  - 예시 : `refactor/#12/component-structure`

## 🌊 Flow

1. Issue 생성
2. 최신 `develop` 브랜치에서 작업 브랜치 생성
3. 기능 개발 및 커밋
4. `develop` 브랜치로 Pull Request 생성
5. 코드 리뷰
6. `develop` 브랜치로 병합
7. 작업 브랜치 삭제
